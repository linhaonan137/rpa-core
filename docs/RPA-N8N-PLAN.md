# RPA 接入 n8n 方案：定时上架 + 未用功能落地

> 回答两个问题：① 元素库之外的 13 项引擎好功能怎么用上；② 定时上架怎么接 n8n（定时调度由 n8n 承担，引擎不再用内置 `trig_time`）。
> 前置阅读：[`TAOBAO-PUBLISH.md`](TAOBAO-PUBLISH.md)（流程现状）、[`WAITING.md`](WAITING.md)（工程技巧）。

## 0. 结论

| 项 | 方案 |
|---|---|
| 定时调度 | 🟢 **n8n Cron**（引擎 `trig_time` 不启用）|
| 触发方式 | 🟢 n8n → `POST /run/qn_publish_draft/async` → 轮询 `/task/{id}` |
| 批量数据 | 🟢 n8n 读 Excel/表 → 逐条注入 `vars`（引擎 `data_sheet_read` 不启用，数据源在 n8n 侧）|
| 可靠性 | `expect` 断言 + `on_fail` 重试 + 幂等去重（P0，接 n8n 前必备）|
| 拟人 | 关键点击 `mode=real` + `verify_text`（P1）|
| 通知 | n8n 侧（企微/邮件），引擎 `notify` 仅做兜底日志 |

## 1. 总体架构

```
┌─ n8n ────────────────────────────────────────────────────────┐
│ Cron（定时上架窗口，如每天 10:05 / 20:05）                     │
│   ↓                                                          │
│ 读待上架清单（Excel / DB / 人工表格）                          │
│   ↓ foreach 每条商品                                         │
│ 幂等检查：查草稿箱是否已有同标题草稿（HTTP 调 RPA 查询或直接跳过）│
│   ↓                                                          │
│ POST http://127.0.0.1:8100/run/qn_publish_draft/async         │
│      body: {"vars": {"宝贝标题": "...", "价格": "...", ...}}   │
│   ↓ 立刻拿到 task_id（不阻塞，浏览器独占由引擎队列保证）         │
│ Wait 节点轮询 GET /task/{task_id}（间隔 10s，最多 20 次）       │
│   ↓                                                          │
│ IF ok → 记录草稿 ID 到结果表                                   │
│   ELSE → 失败分支：read_failure 取现场 → 企微/邮件告警          │
└──────────────────────────────────────────────────────────────┘
                    │ HTTP（同机 127.0.0.1:8100）
                    ↓
┌─ RPA 引擎（有头、登录态常驻）──────────────────────────────────┐
│ Ant 浏览器（用户手动开，RPA_CDP=59493）                        │
│ /run/{flow}/async：队列串行 → flow_run → 结果落 DB             │
└──────────────────────────────────────────────────────────────┘
```

**为什么用 `/run/async` 而不是同步 `/run`**：一条流程 30 秒+，n8n HTTP 节点默认超时会误判失败；async 立刻返回 `task_id`，由 n8n 的 Wait 节点轮询，超时预算自己控制。

**为什么批量用 n8n 的循环而不用引擎 `foreach`**：浏览器是独占资源，引擎队列已保证串行；n8n 侧循环可以做**逐条幂等检查、失败跳过、部分成功汇总**——这些是编排层职责，塞进单条 RPA 流程只会让它更脆。

## 2. n8n 工作流设计（定时上架）

| # | n8n 节点 | 配置 |
|---|---|---|
| 1 | Schedule Trigger | Cron：`5 10,20 * * *`（每天 10:05 / 20:05）|
| 2 | Read Excel（或 DB/HTTP 拉清单）| 列：宝贝标题 / 导购标题 / 价格 / 类目 / 品牌 / 状态 |
| 3 | Filter | 只取 `状态=待上架` |
| 4 | Loop Over Items | 逐条处理，失败继续下一条 |
| 5 | HTTP Request：查重 | 调 RPA `/run/draft_check`（轻量流程：开草稿箱页查同标题），或跳过直接发 |
| 6 | HTTP Request：发品 | `POST /run/qn_publish_draft/async`，body `{"vars": {...}}` |
| 7 | Wait | 10s × 20 次 |
| 8 | HTTP Request：查结果 | `GET /task/{task_id}` |
| 9 | IF | ok → 写结果表（草稿 ID、耗时）；失败 → 10 |
| 10 | 失败分支 | 企微机器人 / 邮件：商品名 + run_id + 失败节点 |

**引擎侧要新增的一个小流程**：`draft_check.json`（开"我的商品"草稿页 → 按标题查重 → `save_as` 返回是否存在），供 n8n 第 5 步调用。这是幂等去重的落地。

## 3. 未用功能 → 落地映射

按阶段做，P0 是接 n8n 的硬前置。

### P0 · 接 n8n 前必备（先做）

| 功能 | 落在哪里 | 具体做法 |
|---|---|---|
| `expect` 事后断言 | `qn_publish_draft` 关键节点 | n16（进填表页）加 `expect:{"url":"publish.htm"}`；n29（保存草稿）加 `expect:{"text":"草稿"}` 或查草稿箱数量变化 |
| `on_fail` 重试 | n7（切标签）、n17（等填表页）等易碎节点 | `{"mode":"retry","attempts":2,"backoff_ms":1500}`；不可逆节点不配 |
| `save_as` 回传结果 | 新增末节点 | 用 `web_elem_info` 读草稿箱计数 `save_as=draft_count`，n8n 从 `/task` 结果的 data 里拿 |
| 幂等去重 | n8n 侧 + `draft_check` 流程 | 同标题草稿已存在 → 跳过（见 §2.5）|
| 连跑 3 次稳定 | 验证动作 | P0 改完后连跑 3 次全绿才算完成 |

### P1 · 拟人与稳定（n8n 跑通后）

| 功能 | 落在哪里 | 具体做法 |
|---|---|---|
| 真实鼠标 `mode=real` | n5（点发布）、n29（保存草稿）、n18/n19（输入可保持 kind=type）| `"mode": "real"`，注意窗口置前（无人值守时段别锁屏）|
| `verify_text` 防点错 | 所有 `@el:` 点击 | 每个点击节点加 `verify_text`，定位退化时直接拒绝 |
| `web_network` 等接口 | n29 之后 | 保存草稿触发接口返回 200 再继续，比等 DOM 稳 |

### P2 · 批量化（单条全稳之后）

| 功能 | 落在哪里 | 具体做法 |
|---|---|---|
| 表格驱动 | n8n 侧为主 | n8n 读 Excel 逐条注入 vars；引擎侧不用 `data_sheet_read`（数据源归 n8n，避免两处维护）|
| 多规格 SKU | 引擎流程 | 尺码/颜色多选时用 `foreach` 循环选项 + `save_as` 收集 |
| 失败通知 | n8n 侧 | 企微机器人；引擎 `notify` 只做兜底 |
| 定期体检 | 独立流程 | n8n 每周调 `/run/element_check`（新流程：跑 `element_verify`，degraded 非空则告警）|

### 不启用（明确不做）

| 功能 | 理由 |
|---|---|
| `trig_time` 定时触发 | n8n Cron 已承担，两处调度只会打架 |
| `llm_selector` / `ai_call` | 无模型 API key；等有 key 再评估改版自适应定位 |
| `record_*` 手动录制 | 用户不手动录；元素库走拾取流程 |
| `subflow` | 有已知缺陷（子流程不共享 browser 引用），用平铺节点 |

## 4. 引擎侧改造清单（n8n 接入前）

| # | 改动 | 工作量 |
|---|---|---|
| 1 | `qn_publish_draft` 加 P0 的 `expect`/`on_fail`/`save_as` | 改 1 个 JSON |
| 2 | 新增 `draft_check.json` 幂等查重流程 | 新流程 ~8 节点 |
| 3 | `/run/{flow}/async` + `/task/{id}` 已有 ✓ | 无 |
| 4 | `/run` 对 `expect` 失败的返回格式确认（failed 列表带节点 id）| 验证即可 |
| 5 | n8n 与引擎同机部署确认（`127.0.0.1:8100`，防火墙无碍）| 检查 |

## 5. 验收标准

1. P0 改完 → **连跑 3 次全绿**（含一次故意断网重连后的重试路径）
2. n8n 手动触发一次完整链路：清单 1 条 → 草稿生成 → 结果表出现草稿 ID
3. 幂等：同一条商品连发两次，第二次被查重跳过，草稿箱不新增
4. 失败路径：故意给一个错的二级类目 → n8n 收到失败告警（含 run_id 与失败节点）
5. 定时：Cron 到点自动跑一轮，全程无人值守（登录态浏览器已开）

## 6. 风险与边界

| 风险 | 边界 |
|---|---|
| 登录态失效（淘宝踢登录）| n8n 每次触发前先跑 `login_check` 轻流程；失败即告警等人，不自动重登 |
| 浏览器被人工占用 | 引擎队列串行兜底；n8n 超时预算 200s |
| 页面改版 | `@el:` 八层降级 + `element_verify` 漂移检测；`expect` 失败即停，不瞎猜 |
| 无人值守锁屏 | 有头模式要求；执行机别锁屏（Windows 组策略或保持会话）|
| 敏感信息 | 商品数据经 n8n vars 传输，不出本机回环；密码类永不进流程 JSON |
