# 一、写坏数据与假成功

## 写坏数据（最贵的一类）

| 现象 | 原因 | 正确做法 |
|---|---|---|
| 流程被改坏后回不去 | `flow_save` 是整体覆盖，没快照 | 覆盖前一律先快照，返回值带快照文件名 |
| `on_fail` / `expect` 写了非法值当时不报 | 直接赋值落盘没过 schema | 写盘前用模型校验，非法直接拒 |
| `limit_steps` 设了没用 | 循环每轮 `new Runner(max_steps=…)` 拿完整预算 | 子 Runner 传**剩余预算** |
| 流程名传 `../xxx` 写到项目外 | 直接用名字拼路径 | 统一 `_safe_flow()` 拒绝 `..` 和分隔符 |
| `element_drop` 报成功，元素还在，库只增不减 | `save()` 是合并写（reload 磁盘后按 key 合并），**合并表达不了"消失"**；内存删掉的条目磁盘上还在，被原样合回来 | 删除必须显式记墓碑（`deleted` 表）+ 文件锁 + 重拾时显式清墓碑；见 `tests/test_elements.py` 四个用例 |

## 假成功（比报错更危险）

| 现象 | 原因 | 正确做法 |
|---|---|---|
| CSV 解析返回空表却 `ok:true` | 参数 `path` 被丢 | 有 path 就读文件填进 text |
| `json_query` 返回空 | 传的 `text` 被丢，节点要 `data` | 映射表补全，改参数必须同步改映射 |
| 写空文件失败 | `content=""` 被当成"没传" | 写入类恒传 content，空串合法 |
| 命令超时后所有响应发不出 | 同步 exec 卡事件循环，`redirect_stdout` 进程级、超时不执行 `__exit__` | **同步 exec 不能放服务进程线程里**，走子进程 |
| 中文乱码 | Windows 输出 GBK，按 utf-8 强解 | 收字节，utf-8 → gbk fallback |
| 新节点调用打到旧实现 | 同名重复注册，`load_all()` 吞异常没人看 | 启动检查 `failures()` 并报警 |

# 二、测试方法论

| 教训 | 具体 |
|---|---|
| **mock 全绿 ≠ 能干活** | 真实站点跑之前，`count()` 永远返回 1、`wait_for` 永远是 AsyncMock，定位链路 bug 一个都测不出 |
| **属性层打桩测不到函数体** | 全绿同时主干函数可以零覆盖。改完必须真跑一次 |
| **自己修 bug 引入的回归更危险** | 缩进、丢内容、加静默分支——字符串替换必须 `assert`，不能 `if` 静默跳过 |
| **CRLF 文件用 `\n` 锚点会静默失败** | 先读 bytes 判换行，或改单行锚点 |
| **单测覆盖不了时序与归属** | P0 基本都出在"哪次调用的结果算数"上 |

# 三、环境陷阱

| 现象 | 原因 | 正确做法 |
|---|---|---|
| 连本地 CDP 报 502 | 系统代理把回环也接走了 | attach 前把 `127.0.0.1` 写进 `NO_PROXY` |
| 调试端口不监听 | Chrome 138+ 禁止默认 profile 开调试 | 复制 profile 到独立目录再启 |
| `.venv\Scripts\python.exe` 找不到解释器 | 宿主运行时目录被重建 | `pyvenv.cfg` 指向随应用分发的 python |
| 后台起的服务下次调用就没了 | 每次调用是独立沙箱 | 起→验证写在同一次调用里 |

# 四、真实站点：定位是重灾区

四类站点（静态 / React SPA / 原生表单 / 带广告 iframe）各跑一遍。三个高频变体同一病根——**判断太早 / 太严 / 错类型**：

| 现象 | 原因 | 正确做法 |
|---|---|---|
| SPA 慢渲染时几十毫秒就报"不存在" | 直接 `count()` 没轮询 | `wait_for(state="attached")` |
| 选择器匹配多个却报"不存在" | 多元素 locator 上 `wait_for` 触发 strict violation | 先 `.first` 再 `wait_for` |
| `li.next a` 永远找不到 | 把含空格当文本，而后代选择器也含空格 | 先判 CSS 元字符再判文本 |
| 打包单文件后只剩十几个节点 | onefile 没目录，`pkgutil` 扫不到 | 节点注册维护显式清单 |

**仍未解决**：

| 问题 | 影响 |
|---|---|
| **属性 vs property** | `<button>` 有 `type` property 无 attribute，`button[type=submit]` 匹配 0 个 |
| **headless 被风控** | 无头弹滑块 → 交付必须有头或接管已有浏览器 |
| **验证码无检测** | 只会傻等到超时再截图，应尽早升到"报人"层 |

**一条认知**：同一份指令，只加一个表达机制（让流程能写"可选分支"）就从失败变成功。**Agent 知道该怎么做但工具做不到——想让 Agent 变强，先看工具能不能表达这件事。**

**B9 怎么绕**：`_all_pages` 把 `ctx.page` 放第一位（适合"找页"），拿它当序号用会漂——
切到第 2 个标签页再列一次，原来的 0 号变成了 1 号。序号统一走 `_stable_pages`
（保持 `browser.contexts[*].pages` 原始顺序）。写流程优先按 URL/标题切，别用序号。

**B10 怎么绕**：`_last_cdp.txt` 里的端点会过期（浏览器关了、Playwright 换随机端口）。
直接 `connect_over_cdp` 撞死端点是 15 秒超时，冷启动就卡在那。接管前先做端口预检
（`_port_open`，0.05 秒），实测从 15s+ 降到 0.53s。

**D5 怎么绕**：MCP / HTTP 服务只在启动时 import 一次代码，改文件不生效。验证前先对时间：

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -match 'mcp' } |
  Select-Object ProcessId, CreationDate
```

进程启动时间必须晚于最后改动的文件。否则你以为在测新逻辑，其实测的是上一版。

**K9 怎么绕**：`_JS_TOKEN` 只匹配 `{单个标识符}`。左花括号后加空格（`{ return ... }`）或用冒号（`{ name: 1 }`）即可避开；`${count}` 会被误替换，写成 `\{count\}`。
