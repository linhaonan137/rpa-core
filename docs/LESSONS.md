# 踩坑台账

> 写调度器、自愈、写回逻辑之前读一遍。每条 = 现象 → 原因 → 正确做法。
> 按「再犯一次会疼多久」排序。不记修复过程，只记判据。

## 一、写坏数据（最贵的一类）

| 现象 | 原因 | 正确做法 |
|---|---|---|
| 流程被改坏后回不去 | `flow_patch` 有版本快照，`flow_save` 是整体覆盖却没有 | 覆盖前一律先快照，返回值带上快照文件名 |
| `on_fail` / `expect` 写了非法值，当时不报，跑起来才炸 | 直接赋值落盘，没过 schema 校验 | 写盘前用模型校验，非法直接拒 |
| `limit_steps` 设了没用，循环照样跑满 | 循环每轮 `new Runner(max_steps=…)` 拿的都是完整预算，跑完再累加 | 子 Runner 传**剩余预算** `remaining = max(1, max_steps - steps)` |
| 流程名传 `../xxx` 能把文件写到项目外 | 流程工具直接用名字拼路径 | 统一 `_safe_flow()`：拒绝路径分隔符与 `..`，所有 flow 工具都接入 |

## 二、假成功（比报错更危险）

| 现象 | 原因 | 正确做法 |
|---|---|---|
| CSV 解析返回空表却 `ok:true` | 参数 `path` 被丢，节点只拿到空 text | 有 path 就读文件内容填进 text |
| `json_query` 返回空 | 传的 `text` / `key` 全被丢，节点要的是 `data` / `path` | 映射表补全，改参数必须同步改映射 |
| 写空文件失败 | `content=""` 被当成"没传" | 写入类恒传 content，空串合法 |
| 命令超时后 MCP 所有响应都发不出去 | 同步 exec 卡住事件循环；`redirect_stdout` 是进程级的，超时后 `__exit__` 不执行 → stdout 泄漏成 StringIO | `python_script` 走子进程（超时真杀进程），**同步 exec 不能放在服务进程线程里** |
| 中文输出乱码 | Windows 命令输出是 GBK，按 utf-8 强解 | 收字节，utf-8 → gbk fallback |
| 加了新节点但调用打到旧实现 | 同名节点重复注册，`load_all()` 把异常吞进 `failures()` 没人看 | 启动时检查 `failures()` 并报警；与幽灵引用检查一起做启动期自检 |

## 三、测试测不到（方法论）

| 教训 | 具体 |
|---|---|
| **mock 全绿 ≠ 能干活** | 真实站点跑之前，`count()` 永远返回 1、`wait_for` 永远是 AsyncMock，定位链路的 bug 一个都测不出来 |
| **属性层打桩测不到函数体** | 全绿的同时主干函数可以零真实调用覆盖。改完必须真跑一次函数体 |
| **自己修 bug 引入的回归比设计缺陷更危险** | 缩进、丢内容、加了静默分支——字符串替换必须 `assert`，不能 `if` 静默跳过 |
| **CRLF 文件用 `\n` 锚点会静默失败** | 先读 bytes 判换行符，或改单行锚点 |
| **单元测试覆盖不了时序与归属** | P0 基本都出在"哪次调用的结果算数"上，必须补时序类断言 |

## 四、环境陷阱

| 现象 | 原因 | 正确做法 |
|---|---|---|
| 连本地 CDP 报 502 | 系统代理把回环请求也接走了 | attach 前把 `127.0.0.1` 写进 `NO_PROXY` |
| 调试端口不监听 | Chrome 138+ 禁止用默认 profile 开调试 | 复制 profile 到独立目录再启 |
| `.venv\Scripts\python.exe` 找不到解释器 | 宿主运行时目录被重建 | `pyvenv.cfg` 指向随应用分发的同版本 python，或重建 venv |
| 沙箱里后台起的服务下一次调用就没了 | 每次调用是独立沙箱 | 用后台任务方式起，验证"起→停"写在同一次调用里 |

## 五、认知：工具能力 > Agent 智力

同一份指令、同一个 Agent，只加一个表达机制（让流程能写出"可选分支"），从失败变成功。

它试过三种办法全失败：加等待（弹窗不来就超时）、用 JS（**引擎没有这个节点类型，被静默跳过**）、调节点顺序（只能改参数，改不了结构）。

**它知道该怎么做，但工具做不到。想让 Agent 变强，先看工具能不能表达这件事。**

## 六、真实站点：定位链路是重灾区

静态页 / React SPA / 原生表单 / 带广告 iframe 的 SPA，四类站点各跑一遍。三个高频变体同一病根——**判断太早 / 判断太严 / 判断错类型**：

| 现象 | 原因 | 正确做法 |
|---|---|---|
| SPA 慢渲染时几十毫秒就报"元素不存在" | 直接 `count()` 判断，没有轮询 | `wait_for(state="attached", timeout)` |
| 选择器明明匹配多个，却报"元素不存在" | 多元素 locator 上调 `wait_for` 触发 strict violation | 先 `.first` 再 `wait_for` |
| `li.next a` 这类后代选择器永远找不到 | 把"含空格"当文本，而后代选择器也含空格 | 先判 CSS 元字符（`#.[]:>*+~,`），再判中文/空格 |

其余只在真实环境才露的：

| 现象 | 原因 | 正确做法 |
|---|---|---|
| 打包成单文件后只剩十几个节点 | onefile 没有文件系统目录，`pkgutil` 扫不到节点目录 | 节点注册维护显式清单 |
| 输入框填空串但报成功 | 节点读 `text`，调用方传 `value` | 兼容两套 + 空值直接报错 |

**仍未解决**：

| 问题 | 影响 |
|---|---|
| **属性 vs property** | `<button>` 有 `type` property 但没有 `type` attribute，`button[type=submit]` 匹配 0 个。CSS 只匹配 attribute |
| **headless 被风控** | 无头模式弹滑块，有头正常 → 交付必须有头或接管已有浏览器 |
| **验证码无检测** | 引擎只会傻等到超时再截图，应尽早识别并升到「报人」层 |
